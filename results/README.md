# What is in results/

## Post-training v2 (pre-registered, Rejected)

| file | what it is |
|---|---|
| `posttraining-v2-manifest.json` | the frozen pre-registration. Written and committed before any training or held-out evaluation ran, and not edited afterwards. Every hash, seed, budget and threshold the study is held to. |
| `posttraining-v2.json` | **canonical.** Every arm at every seed, the gate clause by clause, the control verdicts, the retained checks, resource use, and the implementation notes. |
| `posttraining-v2-report.md` | the same run written for a reader: tables, the gate verdict, and what actually happened. |
| `posttraining-v2-generations.jsonl` | 2,600 rows, one per prompt, arm and seed. Each carries the classifier label computed on the full generation and the first 220 characters of the text, which is the span `src/metrics.is_refusal` reads. Illicit prompts are referenced by JailbreakBench row id; their text is not committed. |

The frozen splits themselves are **not** committed. They are deterministic from
pinned dataset revisions plus the data seed, their sha256 hashes are in the
manifest, and `src/pt2_prepare.py` re-derives and verifies them. Keeping them out
avoids redistributing hh-rlhf rejected responses and a jailbreak benchmark from
this repo.

The verdict is **Rejected**: four of six frozen clauses fail. No number in these
files supports a positive quality claim. `dpo-study-manifest.json` and
`dpo-study.json` are the earlier v1 study, also a rejected record, superseded by
these files.

## The steering sweep

Three separate runs are committed here, at three different sample sizes. They are
not interchangeable, and the numbers in the top-level README come from exactly one
of them. This file says which, so that nobody has to guess why one file says the
alpha=0 response rate is 90% and another says 86.7%.

| file | run | N | is it the canonical result? |
|---|---|---|---|
| `sweep_partial_n100.csv` | main sweep, alphas 0 to 3.0 | 100 benign + 8 held-out illicit | **yes.** Every number in the top-level README table comes from this file. |
| `generations_alpha_2.5_3.0.jsonl` | the same sweep's two collapse points, regenerated | 100 benign + 8 illicit, alphas 2.5 and 3.0 | supporting evidence for the main sweep, see note below |
| `generations_smoke_n3.jsonl` | smoke test | 3 benign + 8 illicit, alphas 0 and 1.0 | no. Shipped only to show the output format. |
| `smoke_test_n3.csv` | smoke test | 3 benign + 8 illicit | no. At N=3 the response rate reads 100%, which is what N=3 buys you. |
| `alpha_diagnostic.csv` | early diagnostic, before the prompt sets were final | 30 benign + 32 illicit | no. Superseded. Kept because it independently shows the same illicit-control climb (40.6% to 100%). |
| `direction.json` | direction learning for the main sweep | 24 training pairs | yes. Layer 23 of 24, Cohen's d = 3.666. |
| `sweep.log` | stdout of the main sweep | | yes. Shows alpha=3.5 starting and not finishing, which is why the sweep stops at 3.0. |
| `tradeoff.png` | figure built from `sweep_partial_n100.csv` | | regenerate with `python src/plot.py --csv sweep_partial_n100.csv` |

**Why the generations at 2.5 and 3.0 were regenerated.** The original sweep wrote its
`generations.jsonl` and that file was lost before it was committed. It was regenerated by
re-running the same two alphas against the same direction. Decoding is greedy with
`do_sample=False` and the model is in eval mode, so the run is deterministic and reproduces
the original; the regenerated direction learning gives layer 23 and Cohen's d = 3.6661, the
same values recorded in `direction.json` from the original run. The regenerated rates match
`sweep_partial_n100.csv` exactly: alpha 2.5 gives 82.0 response / 52.0 coherent / 30.0
degenerate on the benign set and 100.0 / 75.0 on the illicit control, and alpha 3.0 gives
100.0 / 100.0 / 0.0 and 100.0 / 100.0. The intermediate counts also match `sweep.log`
checkpoint for checkpoint. Timing columns are not reproduced from this rerun and the ones in
the CSV are from the original run; the generated text is deterministic, wall-clock is not.

**Why `sweep.csv` is not here.** That is the filename a fresh run writes. It is absent so
that running the pipeline yourself cannot be confused with the committed result.
